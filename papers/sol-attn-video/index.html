第 0 章

热身：视频生成，为什么卡在「注意力」上？

视频每长一秒、清晰一档，token 序列就暴涨一截——而注意力的开销是 token 数的平方。

🎞️ 扩散 Transformer：逐 token「互相打听」的画师

今天的视频生成模型（Wan 2.1、HunyuanVideo、LTX 等）几乎都是扩散 Transformer（DiT）：把视频切成小方块（patch），每个方块变成一个 token，然后让模型从纯噪声开始，一步一步「去噪」成清晰视频。每一步里，每个 token 都要通过注意力（attention）机制去「打听」其他所有 token 的信息，才能决定自己该画成什么样（论文 §1、DiT 原论文）。

问题出在「互相打听」的成本上：序列长度是 L，注意力就要算 L×L 次配对——平方级复杂度。视频 token 又特别长：本文最重的测试是 LTX 2.3 生成 1080p、721 帧的视频（论文 §4.1 表 1），序列轻松冲到几万甚至 12.8 万（128K）token。结果是：注意力吃掉了推理的大部分时间，成为端到端瓶颈（论文 §1）。

一场 12.8 万人的大型相亲会，每个人都必须和在场所有人单独聊一轮——人数翻 10 倍，聊天场次翻 100 倍。这就是注意力在视频生成里的处境。
O = Softmax(QK⊤)V
Q（询问）、K（名片）、V（内容）都是 L×d 的矩阵。QK⊤ 是一张 L×L 的「谁在乎谁」记分表——L=128K 时这张表有 164 亿个格子。FlashAttention 的 online softmax 做到了不把这张大表存进显存，但计算量一格都省不掉（论文 §2、FlashAttention、FlashAttention-3）。

✂️ 稀疏注意力：大多数「配对」其实不值得算

关键观察：注意力记分表里，每个 query 真正高度关注的 key 只有一小撮，其余配对的权重接近于零。块稀疏注意力把序列切成块（本文精确分支用 64×64 的物理块），只为每个 query 块算出「最重要的少数 key-value 块」，其余整块跳过——跳过的格子直接变成省下来的算力（论文 §2、§4.1）。

每个 query 块要和全部 16×16 = 256 个 key 块配对计算。
示意动画：16×16 的块级注意力掩码，每格是一个 key-value 块。绿色 = 实际计算的块；暗色 = 跳过的块。稀疏模式的选中块为示意分布（§4 实验中典型稀疏度约 85%，即只算约 15%）。
免训练（training-free）稀疏注意力的诱人之处：不改模型权重、不用重新训练，直接给预训练模型「换引擎」就加速（论文 §1）。但难就难在——怎么又快又准地选出那 15% 的块？这正是 Sol-Attn 要解决的问题。
第 1 章

旧路由之困：选块的两种老办法，都有硬伤

top-k 太死板、top-p 太神经质，而且两者都得先把整张「代理分数地图」画出来再挑。

🗳️ 代理分数：让每个块派个「代表」先粗评一轮

逐 token 算整张记分表太贵，所以块稀疏方法先做一轮廉价粗评：把每个块里的 token 取平均，得到一个「块代表」向量，用块代表之间的点积作为代理分数（proxy score），估计这个块值不值得精确计算（论文 §2 式 (3)）：

ŝij = Q̄i K̄j⊤，   其中 Q̄i、K̄j 是第 i 个 query 块、第 j 个 key 块的 token 均值
N 个块只有 N×N 个代理分数（比 L×L 小几千倍），这就是「选块」的依据。
像老师不挨个面试 128,000 个学生，而是让每个 64 人的小组派一位「平均分代表」先报个分数，老师凭代表分决定哪些小组值得细谈。

⚖️ top-k 与 top-p：一个一刀切，一个看天吃饭

拿到代理分数后，主流选块策略有两种（论文 §1、图 2）：

策略规则硬伤
top-k每个 query 块固定选分数最高的 k 个块预算僵化：不管这行分数是平是陡，统统选 k 个——分数集中时漏掉重要块，分数分散时硬凑数
top-p从最高分往下选，直到累计概率质量达到 p预算不可控：分布平坦时几乎全选（稀疏度可低至 21.9%），有注意力汇聚点（sink）时只选一两个块（稀疏度可达 96.9%），负载严重失衡

更麻烦的是共同开销（论文所称 L1）：两种策略都要先把整行（乃至整张）代理分数图算完、存进显存（HBM），再排序或累积挑选；长序列下这一步的显存读写和排序开销不可忽略。此外还有 L2：选剩下的块整个丢弃，高稀疏度下精度明显受损（论文 §1）。

第 2 章

核心方法：Sol-Attn 的三板斧

一条会自适应的分数线 + 一趟不落盘的流水线 + 一份「扔掉也要估价」的补偿。

① 随 query 自适应的阈值：τ = μ + βσ

Sol-Attn 的第一步来自一个干净的统计观察：把预训练视频模型里所有行的代理分数 logit 聚合起来看，分布在每个模型内都接近高斯（正态）分布——Wan 2.1、Hunyuan 1.5、LTX 2.3 三个模型都如此（论文 §3.1 图 3）。高斯分布有个好性质：「均值之上 β 个标准差」对应唯一确定的尾部占比 1−Φ(β)。于是选块规则变成（论文 §3.1 式 (4)）：

τi = μi + βσi，   Si = { j : ŝij > τi }
μi、σi 是第 i 个 query 块那一行代理分数的均值和标准差；β 是全局共享的「标准化偏移」。β 定下来，模型整体的平均稀疏度就定下来（≈ 高斯尾部 1−Φ(β)）；但每一行选中几个块，由这行自己的 μ、σ 决定——动态，但可控。
高考录取：top-k 是「每个省都固定录 k 人」，不管这届考生整体水平；top-p 是「从状元往下录，直到录够总人数的 p」，遇上一个超级状元就把名额全挤没了；τ = μ + βσ 则是「每个省按自己这届的平均分 + β 个标准差划线」——每个省录的人数可以不同（动态），但全国总体录取率稳定（可控）。

更妙的是阈值的计算成本：因为代理分数是汇聚后 key 的线性投影，μi 和 σi² 可以直接从汇聚 key 的一阶、二阶矩推出来（论文附录 B 有完整推导），全程只需 O(Ld + Nd²) 时间和 O(d²) 辅助存储——根本不需要把 N×N 的代理分数图具体化出来（论文 §3.1 式 (5)、附录 B）。

② On-the-fly 稀疏化：边扫描边判决，分数不落盘

有了阈值，Sol-Attn 把「选块」这件事直接塞进 online softmax 的流水线里：每个 query 块逐 chunk 扫描汇聚 key 序列，每算出一个块的代理分数就当场和 τ 比较——过线的块立刻派发给内层循环做精确注意力，不过线的走近似分支。因为每个分数「产生即消费」，代理分数图和路由索引永远不需要写进显存（论文 §3.2、图 4、算法 1）。

外层循环（密集扫描）：逐 chunk 读汇聚 key → 算 token-到-块分数块 → 列均值 = 代理分数 → 与 τi 比较
├─ 过线（绿色）：派发给 内层循环，对原始 ⟨Kj, Vj⟩ 块做精确注意力
└─ 不过线（琥珀色）：同一批分数原地复用，做零阶近似修正
两条分支共享同一个 online-softmax 状态（running max、分母累加器），一趟扫完输出即归一
数学上可以证明：分 chunk 的流式阈值判决，选出的块集合与「先算完整行再判决」完全相同（论文 §3.2 式 (6)(7)）。

示意动画：外层循环从左到右扫描 4 个 chunk（每个含 4 个汇聚 key 块）。分数高于 τ（黄线）的块进入右侧「内层精确注意力」，低于 τ 的进入「近似修正」——其分数已在芯片上，复用零成本。右下角：显存里自始至终没有代理分数图。
这趟流水线是单内核（single kernel）完成的：Q 块和阈值驻留共享内存，online-softmax 状态驻留寄存器，路由开销被「吸收」进近似分支的计算里（论文 §3.2 Hardware-Aligned Implementation）。

③ 代理分数复用：被跳过的块，也要「估个价」

传统稀疏注意力的第二大伤（L2）：没选中的块直接扔掉，但它们携带的注意力质量加起来可能不小，稀疏度越高、精度掉得越狠。Sol-Attn 的做法是零阶泰勒近似：把块内每个 key 的指数分数，围绕「块代表分」展开（论文 §3.2 式 (8)）：

exp(QiKj⊤) = exp(QiK̄j⊤) ⊙ [ 1 + Qi(Kj − K̄j)⊤ + 𝒪(·²) ]
只保留第 0 阶项：整块近似成 exp(QiK̄j⊤)——右边这个数就是刚才路由时算过的代理分数，白捡的。论文附录 B 的误差界（式 16）表明：分母的近似误差是块内分数离散度的二阶小量——块内越「齐」，估得越准。

于是 softmax 的分母和分子都变成「精确 + 近似」两段（论文 §3.2 式 (9)(10)）：选中块贡献精确值，未选中块贡献近似值——丢弃变成了降级，信息的「总账」大致保住了。

期末算班级总分时，top-k 是「只统计点名的几个小组，其余小组当不存在」；Sol-Attn 是「重点小组逐人精算，没点名的小组按各自的小组平均分×人数估进去」。总分不会精确到小数点，但量级不会跑偏——而且估分用的平均分，恰好处是点名前就顺手算好的。

另一个侧面证据是和 cuDNN 的块稀疏注意力（BSA，H100 上最强块稀疏实现之一）对比：在相同选中块下，Sol-Attn 的算子因多做了近似修正只慢 1.6%–9.4%；但一旦把 BSA 独立的选路阶段算进端到端，Sol-Attn 反而快 6.2%–6.6%——因为路由几乎被「藏」进了 online softmax 流水线，只剩轻量阈值计算在算子之外（论文 §4.5 图 10）。

🔬 消融：两个设计各自兑现了什么

阈值路由 → 密度稳定。在相同的 15% 平均密度下，top-k 把每个 query 块机械地钉在 15%，top-p 的逐 query 密度则大幅散布；Sol-Attn 的逐 query 密度紧密集中——预算动态，但整体水位稳定（论文 §4.5 图 8）。

近似修正 → 误差更低。在相同选中块下对比「只精确」与「精确+近似」：随稀疏度从 70% 升到 90%，只精确方案的相对 ℓ2 误差快速累积，而带修正的方案误差持续更低、与稠密输出的余弦相似度更高，且稀疏度越高优势越大（论文 §4.5 图 9）。

第 4 章

局限与意义

还不是终点：B200 内核未吃满、只支持前向、自回归视频模型未覆盖。

⚠️ 作者自列的三条局限

论文在结论中坦率给出边界（论文 §6 Limitations）：

· B200 内核还有余量：当前 Blackwell 架构的实现尚未完全发挥硬件潜力；
· 只支持前向推理：没有反向传播实现，想「稀疏化训练」还得等后续工作；
· 评测范围限于双向扩散模型：自回归（AR）视频生成尚未覆盖——那里的因果掩码会让「逐块近似」的推导需要额外处理（附录 B 也指出了这一点）。

另外值得注意的是，本文的阈值校准依赖「代理分数接近高斯」这一经验观察——在已测的 Wan、Hunyuan、LTX 上都成立，但换到分布形态不同的新模型时，β 与实际稀疏度的对应关系可能需要重新校准。

🌏 意义：把「选块」从一个独立工序变成流水线本能

Sol-Attn 更大的启发在于范式层面：路由不再是稀疏注意力之前的一道独立工序，未选中的块也不再是被丢弃的垃圾、而是被降级的信息（论文 §6）。免训练、单内核、即插即用的特性，让它能作为「替换零件」直接装进 Sol-Engine 这类优化推理框架，与缓存、融合等正交技术叠加出 5 倍级端到端加速（GitHub 代码、项目主页）。

一句话总结：τ = μ + βσ 这条会自适应的分数线，加上「分数产生即消费、未过线也复用」的流水线设计，让视频生成的注意力在 85%–90% 稀疏度下既快（端到端 2.1×–3.0×，组合 Sol-Engine 达 5.1×）又稳（质量与相似度全面持平或领先）（论文摘要与 §4）。
